Phân tích toàn bộ framework 14 bài của Claude Academy, đối chiếu với codebase agent-harness (protocol portable, skill requirements, runtime cục bộ, adapter, cầu nối DSH) — rồi đề xuất lộ trình trở thành harness mạnh nhất.

Kết luận tổng

Harness này đã vượt playbook ở kỷ luật bằng chứng và tính portable đa agent. Còn thiếu ở vòng đời artifact, review PR, eval agent và vòng khép kín stage Maintain.

  • Mạnh hơn khóa học: protocol chứng cứ theo từng AC, quy tắc evidence stale, cổng review độc lập, trung thực ASSISTED, threat model, ma trận kiểm soát UPG (24 mục), adapter đa runtime.
  • Yếu hơn khóa học: chưa có pipeline intent.md → spec.md → plan.md first-class, chưa có REVIEW.md, chưa có suite agent-evals trên CI, chưa có vòng bands/metrics tự viết intent tiếp theo.
  • Đường tới harness mạnh nhất: hoàn tất các phase UPG còn mở, rồi import artifact chain + closed-loop của playbook thành skill/hook portable — không hy sinh authority của evidence.

1. Framework playbook

AI-Native SDLC Playbook của Anthropic (14 bài, ~1 giờ) lập luận: khi agent viết phần lớn code, nút thắt dời sang plan / review / deploy. Giải pháp thay thế là vòng lặp các artifact đã commit. Mỗi stage kết thúc bằng việc ghi một file vào version control; stage kế tiếp bắt đầu bằng việc đọc file đó. Con người giữ phán đoán ở cổng (gate), không ở từng dòng code.

Luận điểm cốt lõi

  • Giai đoạn Build co lại; cổng chạy tốc độ con người thành hàng đợi thật.
  • Controls thiết kế cho người viết code không scale được khi agent viết phần lớn diff.
  • Governance phải chạy trong lúc agent hành động (hook), không chỉ ở review meeting.
  • Sự cố production ghi thành intent.md kế tiếp — vòng lặp tự nuôi mình.

Bản đồ 6 stage

  1. Plan — capture thành intent.md
  2. Design — requirements + design → spec.md
  3. Build — plan mode → plan.md; CLAUDE.md; skills; phiên song song
  4. Test — feedback loop; continuous evals trên CI
  5. Deploy — AI review PR; hook làm gate; CI/CD + deploy qua MCP
  6. Maintain — bands / metrics → intent mới

2. Hiện trạng harness

Repo: agent-harness v0.3.0 (private). Kiến trúc đích từ plan 260908-2104-harness-comprehensive-upgrade:

SRS / AC / NFR → task slice đã duyệt → native adapter → recorded execution
→ evidence validation → independent review → derived gates → release decision

Lớp portable (mạnh)

  • protocol/harness-protocol.md — evidence theo AC, bounded retry, cancel, memory là context không phải quyền
  • skills/requirements-spec/ — soạn SRS, EARS, ADR, tracking contract, validator Python
  • templates/task-spec.md + reviewer-prompt.md — hợp đồng review clean-context
  • contracts/harness-runtime/1/*.schema.json — hợp đồng thực thi
  • docs/threat-model.md — ranh giới tin cậy ASSISTED trung thực
  • Ma trận kiểm soát UPG-01..UPG-24 (đề xuất)

Runtime & adapter

  • Runtime TypeScript cục bộ: recorder, evaluator, store (SQLite), memory, installer
  • CLI bin/harness.mjs (doctor, record, evaluate)
  • Adapter: công bố capability portable + plugin host DSH
  • Plugin vendor DSH: MCP settings, tool-arg coerce, replay-dedup
  • Tổng hợp eval offline evals/run.mjs (không gọi model sống)
  • Workflow CI chạy typecheck/build/test/package — không đặt required checks
Trung thực về trạng thái (từ docs): runtime là ASSISTED, không phải sandbox hệ điều hành. Review độc lập, native DSH/browser/Windows, so sánh model trả phí và việc remote required-check từ chối thật vẫn đang chờ. releaseReady:false. Các phase 00–08 của plan vẫn mở cho acceptance đầy đủ.

4. Khoảng trống trọng yếu (xếp theo đòn bẩy)

G1

Chưa có chuỗi artifact first-class

Sức mạnh của playbook là vòng lặp: intent được accept thì kích hoạt design; spec được accept thì kích hoạt plan mode; plan được accept thì kích hoạt build. Harness này kỷ luật evidence rất tốt nhưng artifact phía trên còn phi hình thức (task-spec, plans/). Không có skill intent.md chuẩn + template, harness không tự kích hoạt stage kế hay đo survival/rework từ lịch sử Git.

Khắc phục: thêm skill portable skills/capture-intent + template chung; định nghĩa chuyển tiếp intent→spec→plan thành field hợp đồng; metric: độ trễ intent-commit → spec-commit.

G2

Chưa có suite agent-evals trên CI

evals/run.mjs chỉ tổng hợp observation offline và đánh dấu chưa xác minh độc lập. Playbook coi thay đổi CLAUDE.md/skills/hooks là regression của code và cần suite eval sống. Đây là vòng phản hồi lớn nhất còn thiếu nếu muốn tuyên bố “harness mạnh nhất”.

Khắc phục: 20–50 task thật làm fixture; runner non-interactive; chặn merge config PR theo pass-rate; sự cố → eval vĩnh viễn.

G3

Chưa có vòng khép kín stage Maintain

Không có bộ phát hiện band tất định, không có hàng đợi triage, không tự viết intent.md từ metric production/CI. Harness dừng ở acceptance cục bộ — không tự nuôi mình.

Khắc phục: schema bands.yaml portable + script phát hiện; 1σ log / 2σ diagnose / 3σ propose-PR-or-runbook; mọi đường ra luôn theo format intent Stage-1.

G4

Hook là chữ trong protocol, chưa phải pack portable

Khóa học: PreToolUse production-gate, bảo vệ file test, path được bảo vệ, chặn secret trong diff. Ở đây: authority host DSH + hook global Grok/Codex trên máy operator, nhưng chưa có pack hooks/ ship được cho project đích. Skill advisory mà thiếu hook hard đi kèm vi phạm chính quy tắc “skill là advisory, hook là hard” của khóa học.

G5

Chưa có REVIEW.md / policy review đa pass

reviewer-prompt.md là reviewer một-shot phủ AC. Playbook kỳ vọng review đa pass liên tục (bug / security / compliance-vs-spec+plan) kèm rank severity, chặn nits, và vòng fix @claude. Thiếu phần này, review của người vẫn là nút thắt mà khóa học muốn giải.

G6

Acceptance UPG còn mở nên chưa thể gọi “mạnh nhất”

Plan ghi: review độc lập PENDING; một số check group NO_RESULT; releaseReady false; native DSH/Windows/browser chưa verify. Tuyên bố vượt trội so với khóa học là vô nghĩa cho tới khi UPG-01..24 có test positive+negative thật và reviewer clean-context PASS.

6. Lộ trình tới harness mạnh nhất

Xếp theo đòn bẩy × phụ thuộc, khớp các phase plan hiện có. Mục đánh dấu ★ là import từ playbook; mục còn lại hoàn tất công việc UPG đang mở.

Ngay bây giờ — đóng lõi UPG còn mở (plan phase 00–04)

  1. Baseline + containment regression; hoàn tất suite typecheck/core/operations với log hiện tại.
  2. Schema + evaluator: từ chối empty/zero/skip/cancel thành PASS; quy tắc evidence stale.
  3. Evidence producer + đường review độc lập thật (không phải worker tự nhãn).
  4. Lifecycle: cancel, crash recovery, không blind retry sau timeout mơ hồ.

Tiếp theo — các stage playbook thành skill portable ★

  1. ★ Pack chuỗi artifact: skills/capture-intent + nối skills/requirements-spec + skills/plan-mode commit plan.md và buộc đồng bộ plan↔diff.
  2. ★ Skill REVIEW.md: policy đa pass (bug/security/compliance-vs-spec+plan), Important vs Nit, chặn số nit, bỏ path generated.
  3. ★ Pack hooks: ví dụ PreToolUse portable — path được bảo vệ, bảo vệ sửa file test khi fix, chặn secret trong diff, production-deploy ask/block với thông báo exit-2.
  4. ★ Thư viện subagent: verifier / researcher / simplifier dưới .claude/agents/ + bản portable.

Sau đó — khép vòng ★

  1. ★ Agent evals trên CI: suite task thật; chạy khi PR chạm CLAUDE.md/skills/hooks + hằng đêm; chặn merge theo pass-rate.
  2. ★ bands.yaml + detector: bắt đầu bằng tỷ lệ test-failure CI và thời gian vòng đời PR; tier log/diagnose/propose.
  3. ★ Intent writer từ bands: mọi đường propose 3σ phát intent.md Stage-1 để Maintain nuôi Plan.
  4. ★ Bước judgment trong CI: claude -p triage khi build fail; nháp changelog; mọi ghi đều là PR.

Cuối cùng — quan sát, đừng tuyên bố (plan phase 07–08)

  1. Đo các chỉ số leading/lagging playbook định nghĩa (độ trễ intent→spec, first-pass CI, thời gian review, pass-rate eval, breach→intent).
  2. Reviewer độc lập PASS + quan sát required-check từ chối thật trước khi dùng chữ ENFORCED hay “mạnh nhất”.
  3. Phân phối private cho tới khi license/source-manifest xử lý xong; canary → opt-in → default.

Trạng thái đích (một câu)

Một harness portable, đa runtime, nơi mọi thay đổi đi qua intent → spec → plan → implementation → evidence → independent review → merge có gate, thay đổi config agent bị chặn bởi eval, hook ép policy hard, band production viết lại intent kế tiếp — và mọi PASS đều dựa trên evidence hiện tại chứ không phải tự khai.
